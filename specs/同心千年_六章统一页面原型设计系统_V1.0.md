# 《同心千年》六章统一页面原型设计系统
## UI / UX Design System + Page Prototype Specification V1.0

> 适用范围：汉代、北魏、唐代、元代、清代、当代六章  
> 目标终端：PC / 比赛大屏优先，兼容 16:9 投影与平板横屏  
> 基准画布：1440 × 900  
> 推荐开发：Vue 3 / React + TypeScript + ECharts + GSAP  
> 设计目标：**六章同一套产品系统、不同历史内容拥有不同核心交互，不做六套互不相干的页面。**

---

# 1. 设计系统总原则

整个《同心千年》只保留一套稳定的产品骨架：

```text
进入
↓
看见历史对象
↓
主动探索
↓
理解对象
↓
向AI追问
↓
检查史料
↓
发现关系
↓
形成个人探索成果
```

六个章节共用：

```text
同一个顶部导航
同一个章节进度系统
同一个实体详情抽屉
同一个AI对话框架
同一个史料证据系统
同一个知识图谱框架
同一个探索成果页面
```

差异只发生在：

```text
主场景视觉
核心互动工具
叙事问题
内容实体
AI角色
知识图谱初始结构
```

因此，产品的统一感来自“交互规则一致”，而不是“六章长得完全一样”。

# 3. 六章核心交互签名

| 章节 | 章节主题 | 核心视觉对象 | 专属交互 | 用户第一动作 |
|---|---|---|---|---|
| 汉代 | 相遇 | 丝路历史示意地图 | 路线透镜 / 物品流动 | 点击历史路线节点 |
| 北魏 | 交融 | 云冈—龙门双场景 | 证据对照透镜 | 对比同类文化证据 |
| 唐代 | 交流 | 《步辇图》横向画卷 | 人物关系透镜 | 点击禄东赞等画中人物 |
| 元代 | 共存 | 居庸关云台券洞 | 六体文字透镜 | 点击预标注文字区域 |
| 清代 | 归属 | 东归迁徙地图 | 时间轴 + 路线证据 | 拖动1771迁徙时间轴 |
| 当代 | 传承 | 羌绣数字工坊 | 元素知识 + AI共创 | 先选针法/纹样，再生成 |

统一原则：

> **每章只能有一个最主要的“玩点”。**

避免每章都堆地图、数字人、小游戏、生成器，导致主线失焦。

# 8. 字体系统

优先系统可获得中文字体，不绑定特殊商业字体。

```css
--font-display:
  "Noto Serif SC",
  "Source Han Serif SC",
  "Songti SC",
  serif;

--font-ui:
  "Inter",
  "Noto Sans SC",
  "Source Han Sans SC",
  "Microsoft YaHei",
  sans-serif;
```

使用规则：

- 一级章节标题：衬线体；
- 大型关键词“相遇 / 交融 / 交流 / 共存 / 归属 / 传承”：衬线体；
- 正文、按钮、标签：无衬线；
- 不使用书法字体承载长正文；
- 书法字只允许 Logo 或章节视觉字。

# 93. 最终统一后的产品感受

用户不应该感觉自己在使用：

```text
六个历史小程序
```

而应该感觉是在使用：

> **一个不断展开的中华文化关系探索系统。**

在汉代，他从道路发现联系；

在北魏，他从遗存对照发现文化重组；

在唐代，他从一幅画发现画外人物网络；

在元代，他从一种文字发现多文字共存；

在清代，他从迁徙路线理解历史记忆；

在当代，他从传统技艺走向参与式文化共创。

最终所有体验在：

```text
总知识图谱
+
我的文化足迹
```

重新汇合。

这就是六章统一之后真正完整的产品闭环。
