# 元代篇《石壁上的六种声音》剧情实现说明 V8

## 1. 本轮目标

把《完整剧情重写版 V6.0》从策划文本转化为网页端可完整游玩的章节剧情，并参考 `culture.zip` 中 Godot 元代样章的分层壁画、暖金热点、触摸友好交互和状态模型。

本轮不是把剧本改写成连续文字阅读，而是形成：

> 对白推进 → 观察操作 → 证据入卷 → 判断反馈 → 人物关系变化 → 当代档案校验

## 2. 入口与文件

- 剧情入口：`/chapter/yuan/story`
- 剧情组件：`frontend/src/chapters/yuan/YuanStoryExperience.vue`
- 剧情数据：`frontend/src/chapters/yuan/yuanStory.ts`
- 章节配置：`frontend/src/game/catalog.ts`
- 自动测试：`frontend/tests/e2e_yuan_story_check.py`
- 场景素材：`frontend/public/assets/yuan/story/`

元代任务简报和章节开场现在会进入专属剧情页；旧的六体文字观察场景仍保留在 `/chapter/yuan/scene`，可继续作为自由探索或资料查看入口。

## 4. 状态与反馈

剧情进度保存在浏览器 `localStorage` 的 `tongxin.yuan.story.v6` 中，包括：

- 当前场景与对白位置
- 已查验线索
- 雨水场景的调查立场
- 六张规则卡的分类结果
- 文字与人群问题的回答
- 最终施工判断
- 终局裁决链、核验状态与尝试次数
- 当代档案校验矩阵
- 是否保留旧版校样

刷新页面后可以继续。证据、最终选择与方法倾向同时写入项目原有的 `game` 存档，因此结章页与“千年史册”仍能读取本章结果。

## 5. 三种主要结局

### 甲：过度简化

施工可以继续，但玩家把第一版写成确定的“错误旧稿”。结果提示其历史叙述超出证据。

### 乙：有限确认

采用第二版继续施工，沿用共同标准，保留文本差异，并保存第一版作为版本证据。这是最完整但不是唯一允许的路径。

### 丙：证据不足

暂缓施工，最大程度保存证据，但必须承担工期延误。游戏不会把“承认未知”包装成无成本的正确答案。

## 6. 史实边界

项目内部仍按三层内容管理：

- **史料确证**：1345年、居庸关云台、多种文字题刻、六体不能简单等同六个固定人群。
- **合理重建**：施工协作、校样核对、位置与文本结构的校核方式。
- **剧情虚构**：陈砺、帖木儿、桑结、两份具体校样、雨水事故和当天限时决定。

Godot 素材被标为“剧情场景美术”，不作为云台建筑、人物服饰或题刻版位的精确复原。当前不绘制、不模拟、不随机生成任何未经专家校对的古文字字形。

为避免游玩画面反复解释、打断沉浸感，三层标签及逐场免责声明不再显示在左上角场景标题区；历史边界继续保留在剧情数据、制作文档与页面底部的全局说明中。

## 7. 后续深化建议

1. 为陈砺、帖木儿、桑结分别制作经过史料审校的角色半身像，替换目前以对白姓名区分人物的方式。
2. 取得专家校对的拓片蒙版后，将真实字形接入独立资源槽；未取得前保持留白。
3. 增加音效层：敲石、纸张翻动、雨声、远处车马和门洞风声。
4. 让场景 08 的三个决定在场景 09 中出现更明显但克制的差异反馈。
5. 由历史顾问复核“施工协作”和“校样流程”的合理重建表述，再进入正式发行版本。

## 10. V7 商业闭环升级

本轮把原本“读完对白后三选一”的第八幕改为完整终局推演。玩家需要把前七幕证据放入三层裁决：

1. **确认事实**：两份校样可能承担不同阶段功能，但确切先后未知；
2. **形成行动**：统一外框定位，同时保留内部间距、方向与文本结构；
3. **保留未知**：不把版本先后和文字／人群关系补成确定故事。

三层同时成立后，玩家才会进入施工抉择。抉择不再只有一句反馈，而会改变第九幕的工期、证据、协作三项状态，改变陈砺、帖木儿、桑结和现场负责人的对白，并在第十至十一幕形成不同档案后果。此前是否草率归责、是否区分文字与人群、是否保留旧版，也会进入后续对白。

同时完成以下发行前基础项：

- 场景计数统一为 `01 / 12` 至 `12 / 12`；
- 任务简报使用真实链接，对话框改为原生按钮；
- 关键移动端操作目标提升到约 44px，并补充安全区适配；
- 增加可关闭的轻量纸张、确认、警告与转场音效；
- 增加仅保存在浏览器本地的匿名调试事件，包括错误尝试、解谜完成与最终选择，不上传个人信息。

## 11. V8 中后段推理与重玩闭环

- 第六幕“共同的规矩”从即时判对改为六项规则权限矩阵。玩家完成全部分类后统一核验，错误只定位到断裂项，不再通过逐项变绿猜答案。
- 第七幕“六种文字，多少种人”增加三条人群推断审查：共同空间可确认，实际协作只能有限说明，固定人群不能由文字数量推出。审查成立后，玩家再选择自己的回应语气。
- 两项玩法都进入原有存档、错误尝试统计和移动端单屏测试。
- 元代结章页改为本地路线复盘，显示施工路线、人物信任、旧版能否复核和终局核验次数；不再依赖可选后端摘要才能呈现完整结局。
- 结章页增加“尝试另一条路线”，会安全重置元代章节进度并返回第一幕，形成明确重玩循环。

## 9. V2 深度演出优化

本轮把十二幕统一升级为“拓印证据剧场”式视觉小说演出：整体使用矿物色、墨色、旧纸与暖金提示，保持同一套美术语言，但每一幕都有独立的镜头构图与前中后景组合。

- 十二幕拥有十二种不同的 `framing` 构图；现有六套底图通过裁切、景深、叠层、光色和道具位置组成不同场景，不再重复使用同一张完整背景。
- 对白改为“一屏一人一句”：页面只呈现当前说话者及其形象，上一位角色离场后下一位再进入。
- 取消独立“下一句”按钮；点击或触摸整块对话框即可推进，也支持 `Enter` 与空格键。
- 剧情操作面板只在本场对白结束后出现，避免对白、立绘和玩法同时争夺视觉注意力。
- 增加角色进出场、背景呼吸、雨幕、镜头暗角和场景切换，使叙事节奏更接近商业视觉小说。
- 场景 11 保留证据关系图作为结章视觉中心，对话与封存动作分层呈现。

### 角色素材说明

`frontend/public/assets/yuan/characters/` 中的角色图来自用户提供的 `culture.zip` 内既有 Godot 项目素材，当前作为演出占位合成图使用，用于验证角色位置、尺寸、遮挡关系与对白节奏；它们不代表元代人物服饰的精确复原，也不应直接作为正式发行美术。

正式发行前建议按当前透明 PNG 接口逐一替换为经史料审校的陈砺、帖木儿、桑结、工头半身像。替换时无需修改剧情状态或对白系统。

### V2 自动验收补充

自动测试额外检查：

- 十二幕均具备不同的场景构图标识；
- 至少六套独立背景基底被实际使用；
- 全程通过点击对话框推进，不存在“下一句”按钮依赖；
- 当前页面只显示当前说话者及单句对白；
- 最终证据图、封存动作与章节结束跳转完整可用。

## 10. V3 正式角色立绘接入

陈砺、帖木儿、桑结和现场负责人已从跨章节 Godot 占位素材切换为独立 V2 立绘。四张图片采用一致的古画线描、矿物色与旧纸颗粒语言，同时通过体型、配色、道具和姿态表现各自的剧情职能：

- 陈砺：宽阔、前倾的石作劳动者轮廓，持石工锤与木尺，强调务实、疲惫和可靠。
- 帖木儿：清瘦的校核者轮廓，持校样与细木指示杆，强调克制、审慎和细节意识。
- 桑结：稳定的垂直轮廓，手持相互错开的纸张，强调观察与问题重构。
- 现场负责人：方正的年长工匠轮廓，持卷起工单并指向现场，强调时间压力与实际权威。

原 `*-composite.png` 文件继续保留，仅供回退以及玩家、路人等尚未制作独立形象的次要角色使用。V2 立绘均为透明 PNG，可直接叠加在十二幕背景上，不承担史料图像功能。

## 11. V4 商业化线索玩法

场景 01–05 已由“逐项点击收集”升级为五种不同的证据小游戏：双稿对读、工序接力、版面校准、关系链审查和双稿叠合。小游戏结果继续写入原有证据卷与本地存档，并作为后续规则分类、最终决定和当代档案校验的前置条件。

详细设计、体验目标与试玩指标见 `docs/YUAN_COMMERCIAL_MINIGAME_DESIGN_V1.md`。

## 12. V5 拓纸显影转场

换幕不再只依赖背景淡入，而是采用与本章“拓片、校样、拼合证据”主题一致的三段式演出：

1. 两张带纤维纹理的深色拓纸从左右覆合，暂时收拢旧场景；
2. 中央金线合缝并显出下一幕编号、标题与地点；
3. 拓纸向两侧揭开，新背景以轻微景深和标题显影进入。

转场期间对白输入会短暂锁定，避免连点跳过第一句；场景状态在遮挡完成后切换，证据与存档逻辑不受影响。系统检测到 `prefers-reduced-motion` 时，会压缩为 160ms 的低动态版本。移动端沿用同一构图，但缩短装饰线并把纸纹圆环限制在舞台裁切区内。

左上角现在只保留“时代与地点 + 场景标题”，当前目标仍位于右上角，减少信息层级冲突，让玩家首先读场景和人物，而不是先读制作免责声明。

## 13. V6 单屏证据台

场景 01–05 的小游戏由长表格升级为固定高度、分步切换的单屏证据台。选择先暂存，完成所有局部判断后再统一核验；答错时只定位证据链断点，不直接公布整套答案。场景 10 的档案校验同步改为单条陈述切换，证据卷改为八条一页的按钮分页。

剧情页、玩法面板、档案校验和证据卷均不再依赖上下滑动。自动测试会在桌面端及 390 × 844 移动视口检查页面高度，并验证每个玩法面板的 `scrollHeight` 不超过 `clientHeight`。
