# 统一 AI 问答与联网检索设计

## 目标

- 六个章节的 AI 问答页不再暴露“叙事模式 / 史实模式”切换。
- 问答统一为有来源、谨慎表述的回答风格。
- 用户提问后，后端先执行免密钥联网检索，再让 DeepSeek 结合本地已审核史料和网页摘要组织答案。
- 元代“居庸关云台”问答页左侧显示云台石刻图片。

## 交互

- 对话页标题区只显示当前对话对象，不再显示模式选项。
- 六章都使用各自的默认视觉图；元代默认图为 `/assets/yuan/yuntai-east-wall-original.jpg`。
- 本地史料仍通过原来的来源抽屉查看。联网来源通过新窗口直接打开原网页。

## 后端流程

1. 接收用户原始问题。
2. 先使用 `ddgs` 执行免密钥网络检索，去重并限制条数。
3. 再由 DeepSeek 改写本地检索问句。
4. 读取本地已审核史料并重排。
5. 将网页结果与本地史料作为不同信任等级的证据交给 DeepSeek。
6. 忽略网页摘要里的任何指令，仅把它们当作待核对的外部材料。
7. 继续运行现有确定性护栏、引用校验与降级逻辑。

## 失败处理

- 网络检索超时或不可用：记录日志，继续使用本地已审核资料。
- DeepSeek 未配置或请求失败：保持现有“演示保障模式”，不伪装成实时 AI。
- 本地与联网都无有可用证据：明确返回资料不足。

## 密钥安全

- 仓库只保留 `backend/.env.example`，`LLM_API_KEY` 必须为空。
- 真实 DeepSeek 密钥只由本地 `backend/.env` 或运行环境注入，不写入源码、测试、日志或前端。
- 已在对话中暴露的密钥不会被使用，需在 DeepSeek 控制台废止并更换。
