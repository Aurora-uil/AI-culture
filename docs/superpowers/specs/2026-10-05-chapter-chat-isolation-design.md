# 六章节 AI 助手会话隔离设计

## 目标

六个章节的 AI 助手互相独立。用户在某一章节提出的问题、收到的回答和建立的后端会话，只能在该章节显示。切换到其他章节时显示该章节自己的记录；切换回来时恢复原章节记录。刷新浏览器后仍按现有行为清空，不新增永久存储。

## 状态模型

聊天 Store 维护一个以 `chapterId` 为键的会话桶映射。每个会话桶独立保存：

- `sessionId`
- `messages`
- `character` 与 `chaptersCharacters`
- `recommended`
- `status`
- `currentEntityId`
- `streaming`

Store 同时保存当前激活的 `chapterId`。页面进入或切换章节时，`init(chapterId, characterId, entityId)` 激活对应桶；桶不存在时创建，已存在时恢复。

## 数据流

1. AI 对话页把当前 `chapterId` 传给聊天 Store。
2. Store 激活该章节的会话桶，并只读取该桶的数据。
3. 首次进入该章节时创建专属后端聊天会话。
4. 提问、流式回答、重新回答和停止生成只修改当前章节桶。
5. 切换章节时不清除原桶；再次进入时恢复其消息。

## 并发与边界

- 同一时刻只允许当前可见章节发起一次回答。
- 切换章节时，如果旧章节仍在生成，停止旧请求，避免回调写入新章节。
- 后端会话 ID 按章节保存，绝不复用到其他章节。
- `clear()` 默认只清除当前章节，避免误删其他章节记录。

## 验收标准

- 元代提问后进入唐代，唐代页面不显示元代问题或答案。
- 在唐代提问后返回元代，元代原记录仍存在，唐代记录不出现。
- 六个章节分别拥有不同的后端 `sessionId`。
- 推荐问题、角色和当前实体上下文随章节正确切换。
- 刷新浏览器后记录清空，与现有行为一致。
- 前端类型检查、生产构建和章节隔离端到端测试通过。
