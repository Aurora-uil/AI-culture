# 《同心千年》UI 商业化审视与第一轮优化

日期：2026-10-08

## 1. 产品判断

《同心千年》不是资料网站，也不应被设计成“古风皮肤的信息平台”。它的核心产品形态是：玩家以一个有限身份进入历史处境，通过证物判断、对话和选择，完成一份属于自己的历史记录。

因此界面需要同时承担四件事：

1. 第一秒说明“这是一款可以玩的历史叙事产品”。
2. 让玩家始终知道自己是谁、正在处理哪项证据、还要做什么。
3. 清楚区分剧情重建、证据操作和最终判断。
4. 让史料边界进入操作流程，而不是成为角落里的免责声明。

## 2. 商业文游对标结论

### Pentiment

官方资料强调以泥金装饰手抄本和木刻版画作为完整的视觉世界，而不是只把纹样附着在按钮上；同时提供可调文字大小、易读字体、高对比模式、全键盘操作和无快速反应事件等可读性能力。

可吸收原则：媒介本身就是界面；重文本产品必须把可读性当成功能，而不是补丁。

参考：https://pentiment.obsidian.net/

### Never Alone

文化内容不是独立百科，而是随游玩解锁的“文化洞见”；项目还明确呈现文化社群参与创作的关系。

可吸收原则：文化知识应由行动解锁；来源和参与者应该成为奖励体系的一部分。

参考：https://www.neveralonegame.com/never-alone

### 《画境长恨歌》

产品将诗句、画卷修复和东方绘画交互结合，证明中国文化题材的操作动词可以来自材料本身，而不必套用通用答题框架。

可吸收原则：每章操作语言应该来自对应文物——路线、墓志、画卷、迁徙档案和针线授权，而不是六章共用一种按钮游戏。

参考：https://www.taptap.cn/app/186928

## 3. 优化前的核心问题

| 层级 | 问题 | 商业化影响 |
|---|---|---|
| 首页 | 首屏渐显时间过长，截图和慢设备会短暂呈现为空白 | 第一秒无法形成产品认知 |
| 章节目录 | 画面统一但文字、背景图和游玩状态权重接近 | 玩家难以决定下一步 |
| 章节开幕 | 氛围成熟，但玩家身份与真实主证物没有形成同一信息组 | 角色扮演与史料边界脱节 |
| 剧情舞台 | 对话、场景标题、角色标记都在暗色层中，证据操作出现时层级变化不够强 | 长流程容易疲劳，不易感知“现在该操作” |
| 进度 | 百分比能表达长度，不能表达章节节奏 | 缺少商业叙事游戏常见的阶段期待 |
| 可读性 | 固定字号，对长对白和低视力玩家不够友好 | 文本内容成为进入门槛 |
| 交互 | 对话子元素曾使自动化点击检测误判命中舞台 | 存在整块点击区域不稳定的风险 |

## 4. 本轮设计方向

### 视觉命题

“可游玩的数字档案馆”。

- 剧情阶段：深青暗场，图像与人物声音占主导。
- 证据阶段：抽出一张浅色档案纸，玩家从观看者转为判断者。
- 结论阶段：朱砂或章节色作为唯一高权重确认色。

### 色彩令牌

- 夜档案 `#071412`：剧情舞台背景。
- 深矿青 `#163F43`：主要文字与结构线。
- 档案纸 `#FAF7E8`：证据工作台。
- 旧金 `#D7B768`：进度与时代标记。
- 朱砂 `#B2513D`：行动、争议和确认。
- 雾青 `#CFDFD5`：首页与章节目录空间。

### 排版角色

- 展示文字：宋体系统，承担时代标题、人物姓名和关键结论。
- 正文与操作：黑体系统，承担说明、按钮和证据细节。
- 档案微缩字：小字号、较大字距，只用于编号、来源类型和状态，不承担关键信息。

### 记忆点

九幕档案脊线：剧情顶部不再只显示百分比，而以九段短脊线显示当前幕、已完成幕和后续幕。它既是进度，也是“正在生成一卷档案”的结构隐喻。

## 5. 已落地改动

### 首页

- 去除关键内容的延迟透明动画，保证首秒可读。
- 重新明确产品命题：“在证据与选择之间，看见千年中国”。
- 将六章目录改为真实链接，并直接显示章节结、时长和进入反馈。
- 移除面向开发者的重置按钮，避免破坏正式产品感。

### 章节目录

- 提高文案与背景图对比度，保留文物图像但不让其干扰任务阅读。
- 增加“未启程 / 行至百分比 / 已封存”状态。
- 动作从统一的“进入”改为“领取身份 / 继续行旅 / 重访档案”。
- 已开始章节直接回到剧情，而不是重复经过任务简报。

### 章节开幕

- 将玩家身份、主证物和核验状态放到同一视觉组。
- 主动作改为“进入任务简报”，次动作明确为“直接进入剧情”。

### 剧情舞台

- 加入九幕档案脊线和当前场景名。
- 加入全局持久化的大字模式。
- 对话字号、行高和命中面积提高，增加键盘提示。
- 证据操作改为浅色档案工作台，与剧情暗场形成强烈节奏切换。
- 挑战激活时主动降低人物与背景权重，让操作目标成为唯一视觉焦点。
- 角色牌增加“口述档案”语义，避免只剩抽象印章。

## 6. 后续持续优化顺序

### P0：下一轮必须做

1. 已完成六章统一音效偏好和纸张、确认、警示、转场四级操作音；下一轮补独立环境音量与音量滑杆。
2. 已完成元代独立剧情引擎与五章新引擎的进度、阅读、阶段小结语言统一。
3. 已完成 1366×768 小屏桌面验证；下一轮补键盘焦点回归与对比度自动检查。

### P1：提高留存

1. 已完成：每三幕给予一次“证据卷展开”小结。
2. 已完成：首页显示最近游玩章节、进度，并可一键续玩。
3. 已完成：结算页比较三条路线，只展开本次真实后果，其余路线不剧透。

### P2：提高文化价值感

1. 将来源卡设计为可收藏的“文化洞见”，随操作解锁。
2. 当代章节为创作者署名、授权范围和用途建立可视化权利链。
3. 邀请历史学、博物馆教育和非遗权利专家分别签署章节审核记录，并在产品内可查看。

## 7. 验收标准

- 进入首页 500ms 内必须出现标题、主动作和产品类型。
- 任意剧情场景中，玩家 3 秒内能回答：我是谁、当前第几幕、现在要看还是要操作。
- 桌面和移动端不得产生整页横向滚动。
- 对话卡的中心、文字和继续提示区域都能推进。
- 大字模式刷新后保持。
- 没有完成证据操作时，不能误进入下一幕。
- `prefers-reduced-motion` 下不依赖动画传递必要信息。

## 8. 第二轮优化记录

第二轮完成了产品结构层的统一，而不是要求六章使用完全相同的美术：

- 五章九幕剧情在第 3、6 幕后加入阶段小结，重新陈述已经确认的证据、尚不能推出的结论和下一卷任务。
- 元代十二幕剧情在第 3、6、9 幕后加入拓片式阶段小结，保留其石刻与校勘特色。
- 元代顶部进度改为十二幕档案脊线，与五章九幕脊线形成同一产品语法。
- 元代接入全局大字模式；大字偏好可以跨章节继承。
- 元代音效控制由抽象“声/静”改为明确的“音效开/音效关”。
- 桌面端新增 1366×768 验证，确保导航、对白和场景目标仍保持单屏。
- 阶段小结状态进入本地存档，刷新不会重复打断已经看过的小结。

这一轮刻意保留两种证据台材质：汉至当代五章使用浅色档案纸，元代使用深色拓印校勘台。统一的是信息层级、节奏和操作语言，不是把文物差异磨平成同一套皮肤。

## 9. 第三轮优化记录

第三轮补齐了“进入—游玩—离开—再次回来”的商业文游闭环：

- 首页从笼统的“继续行旅”升级为最近章节直达，显示章节名、章节结和实际任务进度；六章目录仍作为次级入口保留。
- 六章共用 `tongxin.sound` 音效偏好，五章通用剧情与元代独立剧情均使用纸张、确认、警示和转场四类轻量反馈音。
- 结章页新增三路线复盘：本次路线显示真实后果，未走路线只显示选择语义、方法倾向和重玩提示。
- 结章页由强行单屏改为可滚动的通关档案，避免路线复盘加入后压缩正文与行动按钮。
- AI 对话、关系图谱、授权共创统一使用“档案编号—功能名—证据规则”的页头语言，并统一纸张边界、阴影和背景层级。
- 当代共创标题由泛化的“AI 文化共创”调整为“授权共创工作台”，把权利确认置于生成之前。
- 新增 `frontend/tests/e2e_ui_round3.py`，覆盖首页续玩、结章路线、聊天、图谱、共创及移动端三按钮导航。

## 10. 第四轮：从界面优化进入叙事优化

- 将容易造成角色扮演误解的“六段人生”调整为“六个证据现场／六份证据责任”。
- 阶段小结新增“仍可确认的联系”，让史料边界服务于理解交往交流交融，而不是只形成否定性纠错。
- 十八条终局路线均补充“优先保护”和“接受代价”，避免三条选项只是三种同样正确的表达。
- 五章终局选择改为预览取舍后再次确认，降低误触，也为重大判断留出停顿。
- 错误核验累计为修订记录，进入证据卷和结章，不再把学习过程隐藏成一次性答题。
- 唐章玩家身份修正为与实际剧情一致的当代数字导览校对员。

章节层面的完整问题清单与后续顺序见 `docs/NARRATIVE_AUDIT_V2.md`。
